## 发现与处理

优先级用于安排实现前需要固定的约定。P1 表示缺少该约定可能造成错误状态、数据不一致或跨语言故障；P2 表示会造成执行阻塞或可恢复流程遗漏。

| 编号 | 优先级 | 原方案缺口与触发条件 | 已补入的规则 | 负责任务 |
| --- | --- | --- | --- | --- |
| R01 | P1 | 刷新返回 requestedGeneration，但只定义完成扫描的 generation；配置变化、扫描开始与被丢弃扫描缺少可靠通知，按钮可能提前结束或一直等待 | sessionId + stateRevision 订阅；generation 仅计已接受扫描；requestId / completedRequestId 明确请求完成与合并，失败也结束等待 | N07、N09、N10 |
| R02 | P1 | 删除仓库后继续展示旧成功快照，只修正选择；若下一轮失败，列表、摘要与 Widget 可能仍包含已删项。新仓库未读状态也没有定义 | 配置成功提交后立即重投影；删除项消失，新仓库 pending；pending 独立计数，网络动作禁用；配置变化不改成功时间 | N06–N08、N12、N15 |
| R03 | P1 | 主程序重启可能用 pending 空内容覆盖有效 Widget 缓存；Windows 只有文件监听，主程序退出后文件不变，活跃卡片不会自行提交过期状态 | 同 schema / 配置版本匹配时保留首刷前缓存；配置变更及时发布；Windows 活跃期安排过期边界更新，失活取消、重新激活重算 | N13、N16 |
| R04 | P1 | Provider 重启只有“重读文件”的描述；可能没有重新 Create 回调，异步任务也可能继续使用失效的回调上下文 | 用 GetWidgetInfos 恢复已固定实例；回调内复制普通字段；同步实例表与更新，删除后取消待更新 | N03、N16 |
| R05 | P1 | 设置 / 视图 / Widget 字段仍是描述性清单，错误数字状态与 JSON code 未完整映射，容易生成三套不同模型 | N02 建 schema 子集，N09 正式导出前补全；明确必填、可空、反例；真实 Rust 输出贯穿两端测试；等待 TIMEOUT 与 GIT_TIMEOUT 区分 | N02、N09、N10 |
| R06 | P1 | “原子写文件”没有规定何时提交内存；写入失败可能留下内存新配置、磁盘旧配置。配置恢复警告也缺少交付 UI 的通道 | 先持久化再提交内存 / revision / 投影；失败无可见变更；startupWarnings 传递恢复提示；初始化失败不显示为成功空仓库 | N06、N09、N11、N14 |
| R07 | P2 | 总体路线要求两端原型先全部完成；任务图又把整项 N01 / N10 作为依赖，与缺 Mac 仍继续的文字冲突 | N01 / N10 / N17 按 shared / Windows / macOS 子项记录；平台实现只依赖本平台已验证子项，汇总完成仍要求全部 | N00、N01、N10、N17 |
| R08 | P2 | 定时刷新、历史时间与退出已有定义，但休眠恢复、系统时间回拨、加载失败后的重试路径未明确 | 单调时钟调度；定时开启时唤醒合并一次刷新，手动模式保持手动；未来时间显示异常；启动失败可重试且不残留引擎 | N07、N11、N14、N16 |

R04 的平台依据是 Microsoft 对回调对象有效期、Provider 启动恢复与 Activate / Deactivate 的说明；本项目的过期计时是基于这些生命周期约束制定的实现要求。[Microsoft：实现 C# Widget Provider](https://learn.microsoft.com/en-us/windows/apps/develop/widgets/implement-widget-provider-cs)

## 必须转成验证的场景

以下为待实现的验收要求，不是已通过的测试。核心场景优先用可控采集器、时钟和唯一临时目录验证；Widget 系统展示另做真实安装验证。

| 场景 | 操作 | 期望结果 |
| --- | --- | --- |
| 合并请求 | 阻塞正在运行的扫描 A，连续发出 50 个刷新请求，再释放 A | A 后最多启动一轮合并扫描 B；A 不完成 A 启动后收到的请求；B 覆盖最新 requestId |
| 配置使扫描作废 | A 读取旧 revision，期间删除仓库并让 A 完成 | 删除立即可见；A 不发布、不推进 completedRequestId；新扫描覆盖未完成请求 |
| 请求失败与停止 | 请求触发全局失败；另一次请求在完成前停止引擎 | 失败更新完成序号并展示失败；停止唤醒等待者并走 STOPPING，不能伪造成功 |
| 新增尚未读取 | 添加仓库，暂停其首次扫描 | 列表立即显示 pending，total 增加，pendingCount 增加；五种关系与 error 不增加；网络动作不可用 |
| 删除后再失败 | 有历史成功结果，删除仓库，然后使下一次全局扫描失败 | 列表、计数与发布投影都不再出现该仓库；保留其他仓库的历史时间 |
| 设置落盘失败 | 注入原子替换失败，再读取设置并重建引擎 | 返回 SETTINGS_IO；内存、revision、UI 与磁盘仍为提交前版本 |
| 查询结果乱序 | 同状态更换筛选；旧查询延迟返回，其间状态再次更新 | 新筛选不被同代判断丢弃；旧状态 / 旧请求不覆盖新结果 |
| Widget 冷启动 | 保留新原生应用的有效共享文件，重启并暂停首刷 | 配置版本一致时不清空历史 Widget；配置删改或损坏恢复时及时使用新投影 |
| 无新写入时过期 | 主程序退出，保持 Windows Widget 活跃，跨过两倍刷新间隔 | Provider 重新计算并提交过期卡片；等于阈值尚不过期；不启动 Git；实际系统重绘另记录 |
| Provider 恢复 | 已固定组件，重启 Provider，不模拟新的 Create | 恢复实例后可更新；删除与异步更新竞争不会重新建立已删实例 |
| ABI 失败区分 | 分别制造等待超时、Git 超时、设置冲突、同仓库重复操作 | 数字状态 / JSON code 按映射一致，两端产生正确控制流；所有已分配 buffer 释放 |
| 休眠与时钟 | 休眠跨过多个间隔再恢复；模拟时钟回拨 | 定时模式合并一次刷新，手动模式不自发扫描；时间差不下溢，不显示永久新鲜 |
| 启动失败重试 | 注入 DLL / ABI / 数据路径初始化失败，再修复并重试 | 显示明确错误；不覆盖有效 Widget；重试后只有一个引擎、订阅与写入器 |

完整 DTO、请求字段和时间定义以 [实施说明](native-app-implementation.md) 为准。这里不再维护另一套接口示例，避免执行模型在两个定义之间选择。

## 仍需原型提供的事实

- 各平台稳定工具链的准确版本、最低 OS 和首发架构是否由所选工具正式支持。
- Apple 签名身份、App Group 授权、实际共享容器和脱离 Xcode 后的小组件发现 / 读取。
- Windows MSIX 的 Publisher、运行时依赖、COM 激活、实际共享路径及 Widgets Board 中的安装行为。
- Swift / C# 真实调用 Rust 的链接、内存释放和退出验证；Windows 上的 Rust 编译不能代替 macOS 验证。
- 冷启动、空闲消耗与 1 / 20 / 100 仓库扫描的实测基线。原型后重估工作量，不把原先 33–51 人日当保证。

这些项目进入 N00–N04、N10 和 N17–N18 的实际记录，不需要现在重新选择整体技术路线。暂时缺少设备或签名时记录准确子项状态，继续独立工作。
