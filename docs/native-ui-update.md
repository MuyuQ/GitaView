# Windows 原生 UI 修改记录

日期：2026-10-25。基于 `native-app` 的 `600cb25`，修改保留在当前工作区，未提交或推送。本次修改落在现有 Windows WinUI 工程；macOS 尚无主应用工程可同步修改，共同设计要求仍见 `native-app-ui-design.md`。

## 当前版本与第八轮关系文案修复（0.1.5.11）

用户截图中 GitaView 的远端链接可用，当前 native-app 行却显示“无远端”。核查仓库配置：origin 存在，当前分支未配置上游，本地也没有 origin/native-app 引用。后端 no_remote 按现有契约涵盖全部无法进行远端比较的情况，界面不能据此断言没有远端。

行视图保留 HasOrigin / HasCommit：没有 origin 时仍显示“无远端”；有 origin 或条件未知时显示“未比较”。提示列及其完整提示说明未配置 origin、没有可比较的 origin 分支、尚无提交、分离 HEAD 或没有比较结果。筛选与主窗口/托盘计数统一使用“未比较”，托盘空态说明部分仓库缺少远端比较条件。关系枚举、计数排序及 Fetch/Pull/Push 可用规则不变，未修改仓库 Git 配置或执行网络操作。

新增 5 种输入的回归测试，包含从契约行到视图的投影，C# 62/62、Release 构建通过。主包已签名原位更新并启动至 0.1.5.11，Status=Ok，安装 DLL 与本次 Release 产物哈希一致；日志确认主实例进入 ui.rendering。实际新版画面仍待复核。

## 已修改的界面

- 状态页只保留工具栏、分组筛选、状态筛选、仓库表格与结果数量。完整状态摘要移入独立紧凑视图，减少重复标题和统计。
- 统一工具按钮、图标按钮、筛选、输入框、行操作的字号、间距和边界；补充按钮悬停、按下、禁用和系统焦点视觉。仓库行有轻量悬停与选中状态。
- 表格默认采用混合固定/弹性列，最小内容宽度由 820 降为 608；仓库与分支可截断并显示完整内容提示。表头与行同步调宽，支持鼠标拖动及焦点下左右键步进 16。
- 选中行的操作、确认说明、取消入口和执行反馈分层排列；反馈为空时不占用一行。进行中的操作和结果按仓库 ID 与路径保留，快照更新及筛选不重建这些交互状态。
- 设置页保留“仓库设置 / 常规设置”，去掉重复卡片外框；添加和扫描放在同一区域，仓库名和路径按主次排列。常规设置采用连续设置行。
- 增加跟随系统、浅色、深色选择，使用同一套主题角色；高对比度映射系统颜色。主题偏好仅使用 Windows 原生 LocalSettings 的 `appearanceTheme`，没有修改 Rust settings schema。
- 紧凑视图可独立收起/展开，保留页面筛选和选择；正常窗口与最大化窗口都能切换。第二轮调整后的明细最小外窗逻辑尺寸为 640×400，紧凑为 480×144；原生 Presenter 执行限制，按当前窗口 DPI 换算。
- 使用旧版 G 标识替换 WinUI 工程模板占位图。`scripts/native/generate-brand-assets.ps1` 从已有 SVG 的颜色和字标生成 Windows 所需尺寸，标题栏与 ICO 直接复用旧版资产。

## 第二轮：字体、沉浸式标题栏与视觉调整

本轮针对用户提出的“字体发虚、标题栏需要沉浸式、设计有点古老”继续修改，以下记录替代前面关于标题栏和字体的描述。

- 主界面、设置页和紧凑模式分别提供自己的 WinUI TitleBar，Frame 填满整个窗口。主界面的搜索、刷新、设置、收起直接放入标题栏；设置页使用原生返回按钮。移除独立的 Mica 标题条，标题区与内容区采用同一表面颜色；原生窗口按钮随主题调整前景、悬停和按下颜色。
- 保留系统窗口操作，使用 TitleBar 自带的拖动区与交互控件排除机制。主标题栏内容会因刷新按钮文字而改变尺寸，启用 AutoRefreshDragRegions，避免动态布局后点击区域错位。依据：[WinUI TitleBar](https://learn.microsoft.com/en-us/windows/apps/develop/ui/controls/title-bar)。
- UI 字体角色改为 Segoe UI Variable Text，并明确 zh-CN 语言环境；数据名称使用 14，辅助信息使用 13，分支和提交差异使用 Cascadia Mono。统一按钮模板的 FontFamily、FontSize、FontWeight 传递，显式启用布局取整。保留 PerMonitorV2，未修改 Windows 的显示或字体设置。字体角色参考：[Windows typography](https://learn.microsoft.com/windows/apps/design/signature-experiences/typography)。
- 减少数据区逐行分隔线，使用轻量圆角选择区域；分组与状态筛选有不同的强调层级。搜索改为柔和填充输入框。浅色减少蓝灰底色，深色改为更中性的石墨色；仓库关系的颜色语义不变。
- 最近刷新时间移到结果栏，与标题、品牌去重；默认外窗逻辑尺寸调整为 840×560。保留已有仓库表格、分组/状态筛选、行内操作与设置分区。

### 字体检查与图片格式纠正

运行日志确认当前窗口为 `dpi=120`、`rasterScale=1.25`。上一轮通过 Computer Use 获得的图片为 767×534 的 JPEG，保存时误用了 `.png` 扩展名；这些历史图片不能用于判断原生字形清晰度。文件没有凭空变成 PNG，后续不要把扩展名当成格式证据，也不要把 JPEG 转成 PNG 后宣称清晰度提高。

本轮在 Debug 构建中增加原生内容导出快捷键 Ctrl+Shift+F12，使用 RenderTargetBitmap 的默认尺寸与 PNG 编码。当前默认窗口导出为 1032×690，对应约 825.6×552 DIP 的 XAML 内容和 1.25 渲染比例。没有额外放大或锐化。依据：[RenderTargetBitmap](https://learn.microsoft.com/en-us/windows/windows-app-sdk/api/winrt/microsoft.ui.xaml.media.imaging.rendertargetbitmap?view=windows-app-sdk-2.0)。

导出文件在独立测试包的 LocalState/ui-previews，供审阅的副本放在 `target/native-ui-review/lossless/`。带 `-native` 的文件是真正的无损 PNG；早期 `-supersampled` 文件是调试时的额外缩放样本，不作为原生分辨率证据。

**内容导出包含 XAML 标题栏内容，但不包含由系统绘制的最小化、最大化和关闭按钮。** 它不是完整窗口截图。系统按钮、拖动、双击最大化和还原通过实际运行窗口检查；不要把导出中未包含的系统按钮标为软件缺失。

已实际检查：顶部区域拖动、标题栏刷新触发扫描、进入设置和原生返回、浅色/深色融合、紧凑展开/收起、标题区域双击最大化及原生还原。完整 DPI 和辅助技术矩阵仍待验证，本轮 125% 环境下的检查不能替代其他环境。

最终独立测试包为 `GitaView.UIReview 0.1.0.10`。最新无损文件为 `target/native-ui-review/lossless/repositories-light-native.png` 和 `repositories-dark-actions-native.png`；两者均已检查 PNG 文件格式、1032×690 像素尺寸和约 120 DPI 元数据。Debug 导出快捷键需先让内容区获得键盘焦点；其提示不进入产品界面，Release 构建不包含该导出功能。最终 Debug / Release 构建通过，分别保留 9 / 8 项现有警告；42 项 C# 测试通过。
